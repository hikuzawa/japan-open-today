# ADR 0004: 「今日開いているか」の判定・根拠の表示・鮮度の下限

- ステータス: 採用（2026-09-12、事業側の承認済み）

## 背景
このサイトの価値は鮮度そのものである。断定できないときに断定すると、価値がそのまま損害になる（休館日に島まで行かせてしまう）。
静的サイトなので「今日」は生成時点で確定する。閲覧が数日後になっても嘘にならない書き方が必要。

## 決定

### 判定
- `resolve_day(date, hours, closed_rules, special_closures, holidays) -> DayVerdict{state, periods, reasons[]}`
  を sitemill の共通モジュールとして持つ（ADR 0008）
- `state` は **`open` / `closed` / `unknown` の 3 値のみ**。「たぶん開いている」は作らない
- 判定に使う材料の優先順位:
  1. 臨時休業・臨時開館の告知（`special_closures`。日付範囲が当日を含む）
  2. 定休日の規則（`closed_rules`。曜日・第 n 曜日・年間の期間・特定日、祝日時の扱いつき）
  3. 営業時間（`hours`。曜日・季節で切り替わる）
- 祝日は内閣府「国民の祝日」の一次データで判定し、振替休日・国民の休日も反映する（ADR 0008）
- **矛盾したら `unknown`**（例: 規則では開館日だが告知に休館と読める記述がある）。人間が読んで判断できるよう根拠を並べて出す
- 材料が無ければ `unknown`（`no_data`）。推測はしない

### 根拠（必ず表示する）
`reasons[]` は根拠コードと、根拠になった原文の引用・一次情報 URL・取得日時を持つ。ページには文章で出す。
| コード | 表示例 |
|---|---|
| `regular_hours` | 10:00–17:00 開館（入館は 16:30 まで） |
| `weekly_closed` | 毎週月曜休館 |
| `nth_weekday_closed` | 第 2・第 4 水曜休館 |
| `annual_closed` | 年末年始（12/29–1/3）休館 |
| `holiday_open_exception` | 9 月 21 日は敬老の日のため開館 |
| `substitute_closed` | 祝日の翌日 9 月 22 日が振替休館 |
| `special_closure_notice` | 9/15–9/20 は臨時休館の告知あり |
| `stale_source` | 公式ページの取得が 14 日以上できていない（情報が古い） |
| `conflicting` | 規則と告知が食い違っている |
| `no_data` | 開館時間・休館日を公式ページから取得できていない |

### 「今日」の書き方
- **日付を明記した断定しか出さない**。「今日は開いています」ではなく「**9 月 12 日（土）は 10:00–17:00 開館**」
- 併せて **7 日分の帯**（各日の開閉と時間）を出す。数日後に見ても事実として読める
- 判定の基準時刻は日本時間。生成は毎朝 JST 6:00 の日次実行で行う（ADR 0007）

### 鮮度の下限（事業側の追加条件）
- 施設の公式ページの**取得が既定 14 日間成功していない**場合、規則上は開館日であっても判定を `unknown` に落とし、
  根拠に `stale_source`（情報が古い）を出す。閾値は `site.toml` の `[crawl] stale_after_days`
- 取得が途切れているのは、相手サイトの変更・障害・ドメイン移転のいずれかで、規則の前提が崩れている可能性が高い。
  黙って古い規則で断定するより「不明」と言って一次情報へ送るほうが利用者の損失が小さい
- 交通も同じ。運休告知ページの取得が途切れていれば運航状況は `unknown` にする

## 影響
- 日次実行が止まると 14 日でサイト全体が「不明」に倒れる。これは意図した設計で、週次レポートで失敗が見えるようにする
- 判定は生成時に確定するので、索引（`search/<locale>.json`）にも判定結果を入れられる（ADR 0003）

## 追記（2026-09-12）: 実装で確定した根拠コードと、例の訂正

sitemill 側に `openstatus.resolve_day` を実装した（sitemill ADR 0018）。判定の 3 値と根拠の考え方は
上のとおりだが、根拠コードは次の 16 個に確定した。

| コード | 意味 |
|---|---|
| `regular_hours` | 通常の開館時間 |
| `weekly_closed` / `nth_weekday_closed` | 毎週の定休日 / 第 n 曜日の定休日 |
| `annual_closed` / `date_closed` | 年末年始などの期間 / 特定日 |
| `holiday_open_exception` | 定休日だが祝日なので開ける |
| `substitute_closed` | 祝日の振替で休館 |
| `substitute_ambiguous` | 振替先が原文から決められない → unknown |
| `irregular_closed` | 不定休 → unknown |
| `not_in_service` | その日は運行しないダイヤ（交通） |
| `special_closure_notice` / `special_open_notice` | 臨時休業 / 臨時開館の告知 |
| `conflicting` | 規則と告知、または告知同士が食い違う |
| `stale_source` | 一次情報の取得が途切れている |
| `holiday_unknown` | その年の祝日が分からない |
| `no_data` | 材料が無い |

**上の表の `substitute_closed` の例が誤っていたので訂正する。**
「9 月 21 日は敬老の日のため開館、翌 9 月 22 日が振替休館」と書いたが、2026 年の 9 月 22 日は
**国民の休日**（21 日 敬老の日と 23 日 秋分の日に挟まれた平日）である。
「祝日の場合は翌日休館」という規則では、振替先がまた祝日になったときに
「さらに翌日へ動く」のか「当日休む」のかを原文が語っていない。したがってこの日の正しい判定は
`substitute_closed`（休館）ではなく **`substitute_ambiguous` で unknown** になる。
「祝日の場合は翌**平日**」と書いてある施設なら決まり、振替は 9 月 24 日（木）になる。

この違いは実際の香川の施設で起こる（2026 年 9 月は 19 日〜23 日が 5 連休）。
規則の文言を「翌日」と「翌平日」で区別して持つことが、この時期の判定の正しさを決める。

### 告知と規則が食い違うときの決め方（実装）
- 臨時休業の告知は、規則の上で開館日でも休館にする（食い違いではなく追加の事実）
- 臨時開館の告知が定休日の規則とぶつかるときは、**取得日時が新しい方**を採る。
  告知の方が古いか同時刻なら `conflicting` で unknown。根拠はどちらも残す
