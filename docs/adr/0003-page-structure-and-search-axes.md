# ADR 0003: ページ構成と検索軸

- ステータス: 採用（2026-09-12）

## 決定

### URL（`L` はロケールの接頭辞。`ja` は空、英語は `en`、繁体字は `zh-hant`。ADR 0005）
| パス | 内容 |
|---|---|
| `/L/` | トップ。今日の開館状況と運航状況の要約、エリアの入口 |
| `/L/today/` | その日開いている施設の一覧。エリア・カテゴリで絞り込み（静的 JSON 索引をクライアント側 JS で絞る） |
| `/L/areas/<area>/` | エリア。施設カード、地図、そのエリアへの交通 |
| `/L/spots/<area>/<slug>/` | 施設。判定と根拠、7 日分の帯、時間・料金・予約要否、アクセス、一次情報の主ボタン、取得日時 |
| `/L/transport/` | 交通トップ。事業者ごとの運航状況 |
| `/L/transport/<operator>/` `/L/transport/<operator>/<route>/` | 事業者・航路／路線。始発終発・便数・運賃・時刻表リンク |
| `/L/about/` | 運営者情報と免責 |
| `/L/data/` | データについて（出典・ライセンス・用語集の由来・取得日） |
| `/404.html` `/sitemap.xml` `/robots.txt` `/search/<locale>.json` | 共通 |

- エリアの区分は香川県の地域と島で切る: 高松、直島、豊島、女木島・男木島、小豆島、琴平、丸亀、坂出・宇多津、
  東かがわ、三豊・観音寺、さぬき。エリアは `data/sources/kagawa.yaml` の各施設に持たせる
- 施設の `slug` は `<市町コード>-<ローマ字名>` の衝突回避を使わず、エリア内で一意なローマ字名にする
  （URL に市町コードが出るのは空き家の検索性のためで、旅行者向けには読みやすさを優先する）

### 検索軸
- **今日/今週 開いているか** × **エリア** × **カテゴリ** × **予約要否** × **料金（無料／有料）**
- 「今日開いているか」は生成時点で確定した値を索引に入れる（ADR 0004）。索引はロケールごとに分割する

### ページの中身の原則
- 一次情報リンクは常に主ボタン（施設の公式ページ、交通事業者のお知らせ・時刻表）
- 判定・時間・料金には必ず取得日時と根拠を併記する
- 公式の説明文は載せない。紹介文は事実からの自動生成（ADR 0002）

## 影響
- ロケール数 × ページ数だけ静的ファイルが増える。第 1 フェーズの見込みは施設 ~120・交通 ~20 で、3 言語で ~500 ページ
- 「今日」の表記は日付を明記した形しか使わない（ADR 0004）。トップの要約も日付つきで出す

## 追記（2026-09-12）: 「不明」の施設ページの作り

判定が `unknown` のページは、「不明です」だけ出すと利用者に何も渡せない。S6 時点で 12 施設のうち
4 件が unknown なので、ここは例外処理ではなく設計が要る面である。次の順で置く。

1. **日付つきの判定**（「9月12日（土）不明です」）— 断定しないことを先に言う
2. **公式ページへの主ボタンを最大にする**。不明のときに利用者がやるべき次の一手はこれだけなので、
   枠で囲み、幅いっぱい・56px の高さにする。開いている施設のページより大きく出す
3. **判定の根拠を開いた状態で出す**（なぜ不明なのか）
4. **7 日すべて不明なら帯を出さない**。同じ「?」が 7 個並ぶのは情報ではない
5. **分かっている事実は普通に出す**（所在地・電話・料金・予約要否・地図・写真）。
   時間が分からないことと、他が分からないことは別
6. **同じエリアで「今日開いていると分かっている」施設を並べる**。行き先を変えられるようにする。
   並べるのは判定が `open` のものだけ。不明の施設を並べても不明が増えるだけで役に立たない

`stale_source`（取得が途切れている）の unknown は、いつまで確認できていたかを根拠に出す。
