# ADR 0007: 巡回の間隔・日次実行の時刻・デザインの基準

- ステータス: 採用（2026-09-12、事業側の承認済み）

## 決定

### 巡回の間隔（ページ種別で分ける）
akiya-atlas で入れた「変化率に応じた間隔」（sitemill ADR 0015）を再利用する。
| ページ種別 | 間隔 |
|---|---|
| お知らせ・運休告知（`notice`） | **常に毎日**。変化率に関わらず間隔を延ばさない |
| 営業時間・料金・施設詳細（`hours` / `fees` / `spot_detail`） | 変化率に従う（毎日 → 3 日 → 週 1） |
| 一覧・索引（`spot_index` / `route_index`） | 変化率に従う |

- 理由: 臨時休業と運休は「変化が少ないページに突然出る」ので、変化率で間隔を延ばすと最も重要な情報を取り逃がす。
  一方で営業時間や料金のページは年に数回しか変わらないため、毎日取りに行くのは相手サイトへの負荷でしかない
- 実装は `site.toml` の `[crawl] always_daily_kinds`（既定 `["notice"]`）。sitemill 側で間隔判定の前に除外する
- robots.txt とホストごとの間隔は崩さない（sitemill ADR 0003）

### 日次実行
- 毎朝 **JST 6:00** に `crawl → extract → heal → build → deploy`（GitHub Actions の cron）。
  「今日」の判定はこの実行で確定する（ADR 0004）
- 取得が途切れた施設は 14 日で判定が `unknown` に落ちる（ADR 0004）。週次レポートで失敗を可視化する

### デザインの基準（akiya-atlas の `docs/design` を踏襲）
- 数字の帯（stat strip）を H1 直下に全ページ共通で置く
- 信頼ブロック（更新日時・一次情報リンク・運営者・件数。`data-sitemill-trust`）を全ページ必須。欠けるとビルド失敗
- 表よりカード。一次情報リンクは常に主ボタン（外部アイコンと「公式」の明記）
- **システムフォントのみ**（akiya-atlas の計測で Web フォントは LCP +5 秒となり不採用）
- 本文 18px、補助テキストも 16px 未満にしない、タップ領域 44px 以上、色だけに意味を持たせない
- コントラストは本文 7:1 以上、大きな数字と補助テキスト 4.5:1 以上、UI 部品 3:1 以上
- 追加 JS は絞り込みのみ。アニメーションは使わない
- **配色は「生成り × 藍 × 柿渋」**（akiya-atlas の深緑に対して、瀬戸内の別サービスとして色相を変える。
  構造とコントラスト基準は同じ。具体的なトークンは実装時に `docs/design/` に記録する）

## 影響
- `always_daily_kinds` と `stale_after_days` は sitemill 側の実装（S2）が入ってから `site.toml` で有効になる
- 巡回件数の見込み: 施設 ~120 × 1〜3 ページ＋交通 ~20。うち毎日取るのは告知系の ~30 ページ
