# ADR 0010: 1 枚で複数施設を扱うページの切り分け

- ステータス: 採用（2026-09-12）

## 背景

同じ運営者が複数の施設を持つ場合、お知らせ・開館カレンダー・利用案内が**1 ページにまとまる**。
ベネッセアートサイト直島の `/news/` と `/calendar/` には、地中美術館・ベネッセハウス・
豊島美術館・李禹煥美術館・家プロジェクト・犬島精錬所美術館の休館が並んでいる。

S5 ではこのページを情報源から外していた。1 施設に紐づけるしかなく、他館の休館をその館の
休館として公開してしまうためである。しかし S6 の発見が `/news/` を「ニュース」というラベルから
3 施設の `notice` として seed し直し、実際に事故が起きた。豊島美術館のレコードに

- 家プロジェクト「きんざ」 臨時休館 2026-10-13〜2027-01-01
- 李禹煥美術館 一部展示替えに伴う臨時休館 2026-11-24〜12-12

が入り、**豊島美術館の休館として判定に使われていた**。開いている施設に「休館」と出すのは、
このサービスで最も避けたい誤りである。

## 決定

### 1. 共有ページは施設を持たない情報源として切り出す

`data/sources/*.yaml` に、`spot` を持たず `covers`（扱う施設の `spot_id` の一覧）を持つ情報源を
置き、そのページを `kind: shared_notice` にする。施設側の情報源はこの URL を seed しない。

### 2. 割り当ては「告知が名指しした施設名」だけで行う

`shared_notice` の抽出は、告知ごとに `facility_quote`（対象施設名の原文）を返させる。
引用なので本文に実在することを検証したうえで、`covers` の施設の表示名・別名（`aliases`）と
照合する。完全一致 → 包含関係、の順に見て、**候補が 1 つに絞れない告知は捨てる**。

捨てる条件:
- `facility_quote` が `null`（「全館」「アート施設」「豊島」のような書き方）
- `covers` に無い施設（李禹煥美術館など）
- 複数の施設に当たる表記

「同じ運営者の別の館だから近いほうに寄せる」ことはしない。告知 1 件を捨てる害は、
別の施設に休館を出す害よりはるかに小さい。

### 3. seed から外した URL 由来の告知は記録からも消す

`finalize` で、告知の `evidence.source_url` がその情報源の現在の seed に無ければ落とす。
情報源の設定を直しても、記録に残った告知はページに出続けるため。

### 4. 発見は他の情報源が seed 済みの URL を提案しない

複数の施設が同じ URL を指していれば共有ページである。1 施設の `notice` として seed し直さない
（`tools/discover_pages.py`）。設定そのものも `tests/test_shared_notices.py` で検査する。

## 影響

- ベネッセの共有ページから、地中美術館の長期休館（2027-01-12〜03-19）が正しく入った。
  同じページの 15 件は名指しが一致せず捨てた（その大半は収録していない館の告知）
- 「2027年1月〜3月」のように月しか書かれていない告知は日付が読めず捨てる。これは変えない。
  正確な日付は各施設のページかカレンダーに出るので、そちらから取る
- `covers` を持つ情報源は施設ページを持たないので、サイトのページ数は増えない

## 代替案と却下の理由

- **共有ページを 1 施設に紐づけて、他館の告知は表示側で弾く**: 判定は記録から計算するので、
  表示側で弾いても判定には入る。根本の切り分けが必要。却下
- **ページ内の見出し構造で施設ごとに分割する**: サイトごとに構造が違い、変わると静かに壊れる。
  名指しの引用のほうが単純で、外れたときは「捨てる」側に倒れる
- **告知を `covers` の全施設に適用する**: 今回の事故そのもの。論外
