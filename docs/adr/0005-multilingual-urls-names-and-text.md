# ADR 0005: 多言語の仕組み（URL 配置・hreflang・施設名・文章）

- ステータス: 採用（2026-09-12）

## 背景
読者は主に海外からの旅行者だが、一次情報は日本語で、事実の突き合わせも日本語で行う。
機械翻訳の文章を並べると、事実が原文からずれたまま 3 言語に広がる。

## 決定

### URL の配置
| ロケール | 接頭辞 | `html lang` | `og:locale` |
|---|---|---|---|
| 日本語（基準） | なし（`/`） | `ja` | `ja_JP` |
| 英語 | `/en/` | `en` | `en_US` |
| 繁体字 | `/zh-hant/` | `zh-Hant` | `zh_TW` |

- 全ページに `hreflang` を相互に付け、`x-default` は日本語に向ける
- 日本語を基準（ルート）にする理由: 一次情報が日本語で、`/about` などの公開前検査も日本語で行うため。
  海外からの導線は `/en/` が入口になるので、トップに言語切り替えを常時置く
- 表示名は sitemill の i18n カタログ（`i18n/<locale>.yaml`）に置く。`site.toml` の `name` は正式名
  「Japan Open Today」1 つに固定し、各言語の短い表記はカタログ側で差し替える

### 事実の描画
- 時間・料金・休業・運航などの事実は、**構造化データから各言語のテンプレートで描画する**。
  文章を翻訳するのではなく、言語ごとに数字と単位の並べ方を決める（例: `¥2,100` / `2,100円`）
- 日付・時刻・曜日・数値・金額はロケール別のフィルタで整える（sitemill の i18n。ADR 0008）
- 描画時に LLM は使わない。同じデータからは常に同じ HTML が出る

### 施設名・路線名
1. **公式が提供する表記を優先**。公式サイトに英語・繁体字のページがあればその表記を引用として取り込み、
   `source: official` と根拠 URL を残す
2. 無ければ **用語集**（`data/glossary/<locale>.yaml`）に固定した訳を使う。用語集は LLM が一度作って**凍結**し、
   変更は差分としてレビューする。由来は `source: glossary` として `/data/` に明示する
3. 用語集にも無ければ**日本語表記のまま出す**（ローマ字化した推測名は作らない）

### 紹介文
ADR 0002 のとおり、構造化した事実からの自動生成。原文の転載も、原文の機械翻訳もしない。

## 影響
- ロケールを増やす作業は「カタログ 1 ファイル＋用語集 1 ファイル＋テンプレートの文言」に収まる
- 施設名の出典（公式表記か用語集か）がデータに残るので、`/data/` で説明できる
- sitemill 側に i18n（ロケール定義・カタログ・ロケール別フィルタ・hreflang・相互参照の検査）を足す（ADR 0008）

## 追記（2026-09-13）: 施設名の英語・繁体字を、辿って確定する 4 経路

香川全域に広げた時点で 96 施設のうち 84 件に訳が無く、多言語サイトとして読めない状態だった。
名前は**推測で作らない**という原則を保ったまま自動で解決するために、経路を 4 つに決めた
（`tools/resolve_names.py` が 1〜3、`tools/translate_names.py` が 4）。

| 経路 | 何を見るか | `source` |
|---|---|---|
| 1 | 施設の公式サイトのその言語のページ（`hreflang`・「English」のリンク・`/en/`） | `official` |
| 2 | 自治体・観光協会のその言語のページ（同じ仕組みで、一次情報のページから辿る） | `official` |
| 3 | Wikipedia 日本語版の記事からの言語間リンク（英語版・中文版の記事名） | `glossary` |
| 4 | 上のどれも無いとき、用語集に**固定訳を作る**（LLM。名前だけを渡す） | `glossary` |

確定したものは `data/glossary/<locale>.yaml` に、由来・根拠 URL・確認日つきで書く。
**凍結**し、変えるときは差分で見る。既にある訳は上書きしない。

### 判定で守っていること（実測で見つけた誤りから）

- **字種で確かめる。** 英語の欄にかな・漢字が入っていたら採らない。繁体字の欄に簡体字
  （四国水族館の中文ページから「四国水族馆」）や英語（高松市美術館の繁体字に
  「TAKAMATSU ART MUSEUM」）が入っていたら採らない
- **そのページが元のページに対応していることを確かめる。** 「English」のリンクはサイトの
  英語トップに飛ぶことが多く、そこから採るとサイト名が施設名になる（「VISIT KAGAWA」）
- **Wikipedia は場所の記事に限る。** 見出しが施設名と一致し、座標か「香川」があること。
  でないと一般名詞の記事に当たる（「株式会社」から Joint-stock company を採りかけた）
- **英語版が無くても、独語・仏語版の記事名は確立したローマ字表記として採る**
  （弥谷寺 → Iyadani-ji）。こちらで作るローマ字ではない
- Wikipedia の API（`/w/api.php`）は robots.txt が拒否している。記事ページから辿る

### 経路 4（固定訳）の位置づけ

LLM に渡すのは**名前だけ**で、営業時間・料金などの事実には触らせない（ADR 0002）。
出力は用語集に `source: glossary` と「固定訳（公式表記・Wikipedia が無いため作成）」の注記つきで
書き、公式表記が見つかったらそちらが優先される（経路 1・2 が上位）。
訳せないものは**入れない**。日本語のまま出す。

### 結果（2026-09-13）

- 英語 66/96（公式 10・用語集 56）、繁体字 73/96（すべて用語集）
- 残りは日本語のまま。多くは固有名詞そのもの（「NAGARE」「ジョージ」）や、
  命名権の名前（「レクザムホール」）で、確立した表記が見つからなかったもの
