# ADR 0012: 広告の掲載場所・ASP 規約の検査・クリックの計測

- ステータス: 採用（2026-09-13）
- 関連: ADR 0006（アフィリエイトの方針）の「契約後は `/go/` 経由」を具体化する。
  akiya-atlas の ADR 0010 の移植

## 背景

運営者情報とプライバシーポリシーが入り、アフィリエイトの申請に進める状態になった。
契約が下りてから掲載の作法を考えるのでは遅く、**申請の前に導線と検査を用意しておく**。

akiya-atlas で同じ仕組みを作って運用しており、そこで踏んだ問題（計測 URL の `&` が HTML で
`&amp;` になり「宣言していないリンク」と誤検出される、計測 URL が未設定の案件が検査を素通り
する、広告表記がスクロールしないと見えない位置に落ちる）は既に直っている。作り直さずに移植する。

## 決定

### 1. 掲載場所は枠（placement）として宣言する

| 枠 | 場所 | 置ける種別 |
|---|---|---|
| `spot-tickets` | 施設ページの「宿・体験」欄 | 入場券・体験 |
| `area-stay` | エリアページの「宿・体験」欄 | 宿泊 |

- **トップ・交通・データ・運営者情報には広告を置かない**。広告リンクが無いので広告表記も出さない
- 同じ種別に複数社が承認された場合、既定は `rank` の小さい 1 社だけを出す（akiya と同じ理由。
  静的サイトではローテーションも配置時点で固定されるため採らない）

akiya-atlas との違いは、**枠が 1 ページではなく数百ページに出る**こと。枠はページのパスではなく
接頭辞（`spots/` `areas/`）で宣言し、検査はその接頭辞に一致する全ページを見る。

### 2. ASP の掲載規約はデータとして持ち、ビルド時に検査する

`affiliates.py` の `Asp`（広告表記の要否・`rel="sponsored"` の要否・計測 URL の許可ホスト・
禁止表現）を唯一の根拠として、`ad_check.py` が `dist` を検査する。1 件でも食い違えば配置しない。
検査項目は akiya-atlas の ADR 0010 と同じ 7 つ。

**許可ホストが空のままの ASP に計測 URL を入れたら止める**。Klook・Agoda・Booking.com は
まだ提携前で、規約と実際のリンクを見ていない。空欄を「制約なし」と読んで公開してしまわないよう、
空のまま広告が出たら検査が落とす。

飛び先 URL の制約はネットワークに出ないと確かめられないため検査に含めず、登録時に人が 1 度だけ
確認する（akiya と同じ）。

### 3. クリックは転送ページで数える

`<ロケール>/go/<案件>/<枠>/` を noindex の転送ページとして生成し、そこから計測 URL へ転送する。
計測ビーコン（Cloudflare Web Analytics）が 1 回動くので、枠ごとにクリック数が積み上がる。

**転送ページはロケールごとに 1 枚**出す（akiya は 1 言語なので 1 枚）。英語・繁体字の利用者に
日本語の「広告主のサイトへ移動します」を見せない。枠を含まない `/go/<案件>` の 302 は素の導線
として `_redirects` に残す。

## 影響

- 契約前のいまは案件 0 件。枠も転送ページも `_redirects` の行も 1 つも出ず、施設ページと
  エリアページには「準備中」が出る。`ad-check` は「有効な案件 0 件」で通る
- 契約が下りたら `affiliates.py` の 1 案件に ASP・計測 URL・規約を入れるだけで、掲載・転送
  ページ・検査・掲載 URL の一覧（`ad-urls`）がつながる
- `/about/` と `/privacy/` の広告に関する記述は `ads_live` で切り替わる。案件が入った日に
  「掲載していません」から開示文へ変える（テンプレート側の分岐、3 言語）
