# ADR 0012: 広告の掲載場所・ASP 規約の検査・クリックの計測

- ステータス: 採用（2026-09-13）
- 関連: ADR 0006（アフィリエイトの方針）の「契約後は `/go/` 経由」を具体化する。
  akiya-atlas の ADR 0010 の移植

## 背景

運営者情報とプライバシーポリシーが入り、アフィリエイトの申請に進める状態になった。
契約が下りてから掲載の作法を考えるのでは遅く、**申請の前に導線と検査を用意しておく**。

akiya-atlas で同じ仕組みを作って運用しており、そこで踏んだ問題（計測 URL の `&` が HTML で
`&amp;` になり「宣言していないリンク」と誤検出される、計測 URL が未設定の案件が検査を素通り
する、広告表記がスクロールしないと見えない位置に落ちる）は既に直っている。作り直さずに移植する。

## 決定

### 1. 掲載場所は枠（placement）として宣言する

| 枠 | 場所 | 置ける種別 |
|---|---|---|
| `spot-tickets` | 施設ページの「宿・体験」欄 | 入場券・体験 |
| `area-stay` | エリアページの「宿・体験」欄 | 宿泊 |

- **トップ・交通・データ・運営者情報には広告を置かない**。広告リンクが無いので広告表記も出さない
- 同じ種別に複数社が承認された場合、既定は `rank` の小さい 1 社だけを出す（akiya と同じ理由。
  静的サイトではローテーションも配置時点で固定されるため採らない）

akiya-atlas との違いは、**枠が 1 ページではなく数百ページに出る**こと。枠はページのパスではなく
接頭辞（`spots/` `areas/`）で宣言し、検査はその接頭辞に一致する全ページを見る。

### 2. ASP の掲載規約はデータとして持ち、ビルド時に検査する

`affiliates.py` の `Asp`（広告表記の要否・`rel="sponsored"` の要否・計測 URL の許可ホスト・
禁止表現）を唯一の根拠として、`ad_check.py` が `dist` を検査する。1 件でも食い違えば配置しない。
検査項目は akiya-atlas の ADR 0010 と同じ 7 つ。

**許可ホストが空のままの ASP に計測 URL を入れたら止める**。Klook・Agoda・Booking.com は
まだ提携前で、規約と実際のリンクを見ていない。空欄を「制約なし」と読んで公開してしまわないよう、
空のまま広告が出たら検査が落とす。

飛び先 URL の制約はネットワークに出ないと確かめられないため検査に含めず、登録時に人が 1 度だけ
確認する（akiya と同じ）。

### 3. クリックは転送ページで数える

`<ロケール>/go/<案件>/<枠>/` を noindex の転送ページとして生成し、そこから計測 URL へ転送する。
計測ビーコン（Cloudflare Web Analytics）が 1 回動くので、枠ごとにクリック数が積み上がる。

**転送ページはロケールごとに 1 枚**出す（akiya は 1 言語なので 1 枚）。英語・繁体字の利用者に
日本語の「広告主のサイトへ移動します」を見せない。枠を含まない `/go/<案件>` の 302 は素の導線
として `_redirects` に残す。

## 影響

- 契約前のいまは案件 0 件。枠も転送ページも `_redirects` の行も 1 つも出ず、施設ページと
  エリアページには「準備中」が出る。`ad-check` は「有効な案件 0 件」で通る
- 契約が下りたら `affiliates.py` の 1 案件に ASP・計測 URL・規約を入れるだけで、掲載・転送
  ページ・検査・掲載 URL の一覧（`ad-urls`）がつながる
- `/about/` と `/privacy/` の広告に関する記述は `ads_live` で切り替わる。案件が入った日に
  「掲載していません」から開示文へ変える（テンプレート側の分岐、3 言語）

## 追記（2026-09-22）: Klook は施設ごとに飛び先を選ぶ

Klook の提携が承認された（aid `135769`）。計測されるのは `www.klook.com` の任意の URL に
`?aid=` を付けた形だけで、短縮形の `s.klook.com` は計測されない。

### 飛び先の決め方（運営者が決めた）

`src/japan_open_today/klook.py` の対応表で、施設ごとに次の順に選ぶ。

1. **施設の名前が商品名にそのまま出る商品**（3 文字以上の施設名が含まれること）。
   いまは父母ヶ浜（夕日シャトルバス）と、金刀比羅宮・四国水族館（高松発チャーター）の 2 商品。
   文言は「〇〇を訪ねるツアー・体験」で、入場券のようには見せない
2. 商品が無い**直島町**の施設 → Klook の「香川郡」の目的地ページ（文言は「直島のツアー」）。
   **高松市**の施設（女木島・男木島を含む）→「高松市」の目的地ページ
3. それ以外 → 運営者がブラウザで取った「香川」の検索結果ページ

**地中美術館には Klook の商品が無い。** Klook の地中美術館のページに載っていた商品は
岡山の夜光虫ツアー 1 件だけだった。予約は公式だけなので、「予約」とは出さない。

### URL は Klook のサイトマップから辿った

Klook の robots.txt は全ボットに `*/search/*` と `*/searchresult/*` を禁じている（素の HTTP は
403 でも拒まれる）。検索結果は辿らず、robots.txt の `Sitemap:` → サイトマップ → 目的地・商品の
ページ → 各ページの hreflang、とリンクだけで辿った。英語・繁体字の URL も hreflang から取った。

Klook の「香川郡」（`c31301-kagawa`）は**県ではなく郡**。サイトマップに香川県のページは無い。

### 公開の条件と検査

- **ASP の `terms_checked_on`（規約を写した日）が空のあいだは、案件を公開しない。**
  規約を見ないまま「制約なし」と読んで出さないため。全 ASP に効く
- 飛び先の 1 つでも URL が欠ければ、案件全体を公開しない（検索結果 URL を待っている）
- 転送ページは**飛び先ごと・ロケールごと**に出す（`/go/klook-tickets/spot-tickets/<飛び先>/`）。
  施設から飛び先への押された数が分かる
- `ad-check` は、枠のページがその案件のどれかの転送ページを指していること、各転送ページの
  送り先が許可ホスト（`www.klook.com`）で、**生成されたリンクが `aid=135769` を持つこと**を見る
- 案件が公開されると、`/about/` と `/privacy/` の広告の開示文が自動で切り替わる（`ads_live`）

### 案Bで広告表記の位置を変えた

案B（ADR 0013）では本文の先頭が藍のヒーロー帯なので、本文の中に置いた広告表記が冒頭から
約 2,500 文字目になり、「ファーストビューに出す」の検査（1,200 文字以内）に落ちた。
**広告表記はヒーロー帯の一番上**に置く（施設・エリアのページ）。

### 週次の点検

`tools/check_klook.py` を週次まとめに入れた。サイトマップ（robots.txt が許すもの）を
このサイトの巡回用 UA で 4 回だけ読み、対応表の商品・目的地がまだ載っているかを見る。
**香川の検索結果ページは取りに行かない**（robots.txt が禁じている）。人がブラウザで開いて
確かめる項目として、週次に URL を出す。
