# ADR 0009: 情報源の発見、運営主体の判定、人間レビューの最小化

- ステータス: 採用（2026-09-12、事業側の承認済み）

## 背景
巡回してよいのは公式の情報源だけ。空き家バンク（akiya-atlas）は「自治体が運営主体」で線を引けたが、
観光施設は運営主体が多様（市町、指定管理者、公益財団、社寺、民間企業の自社施設、交通事業者）。
それでも「施設自身の公式サイト」であることは根拠として記録できる。

## 決定

### 巡回してよい運営主体（いずれも根拠の引用と URL が必須）
| `operator_kind` | 例 |
|---|---|
| `municipality` / `municipality_affiliated` | 市町の施設、指定管理者が運営する市町の施設 |
| `prefecture` | 県立の施設 |
| `tourism_association` | 県・市町の観光協会 |
| `facility_official` | 施設自身の公式サイト（社寺、公益財団が運営する美術館など） |
| `transport_operator` | 鉄道・バス・旅客船の事業者の公式サイト |

- `third_party`（民間の予約サイト・まとめサイト）と `unknown` は**絶対に巡回しない**
- 民間の予約サイトは、収益導線（ADR 0006）以外では案内しない

### 解決の順序（AI が取れる情報を尽くす）
1. **公的な施設一覧**から施設リンクを集める: 香川県公式、香川県観光協会、各市町公式、各市町観光協会
2. リンク先のホストを施設公式として確定する。`.lg.jp` はドメイン種別そのものが根拠になる
3. **運営主体の根拠を自動で記録する**:
   - 公的一覧からのリンク（＝相互リンク根拠。最も強い自動シグナル）
   - 公式サイト内の表記の引用（`Copyright © ...`、`指定管理者: ...`、`運営: 公益財団法人 ...`、`○○市 ○○課`）
4. **分類に応じて自動採用する**: 施設一覧 / 施設詳細 / 営業時間 / 料金 / お知らせ / 時刻表 / JS 描画 / 第三者予約サイト。
   静的に読めるものは巡回、JS 描画と第三者はリンクのみ
5. ここまでで運営主体が判定できないものだけ `policy: pending` でレビュー行列（`data/review/kagawa.yaml`）に残す

### 人間レビューの原則
- **人間レビューに回すのは、AI が取れる情報を尽くしても運営主体を判定できない案件だけ**にする
- レビュー待ちが **10 件を超えたら「発見側の作り込み不足」とみなし、発見・判定側を直す**。
  人間に配る前に、試した情報源と失敗の理由を必ず添える
- 提示は sitemill の `ReviewQueue`（対象・候補 URL・分類・確信度・根拠・提案アクション）をそのまま使う

### 自己修復
巡回したのに成果が 0 件の source は、`heal` フックで候補を選び直す（akiya-atlas と同じ仕組み）。
施設サイトはドメイン移転・リニューアルが多いため、公的一覧からの再解決を優先する。

## 影響
- sitemill 側の巡回ゲートは二段（`Source` の検証＋サービスの宣言）にする（ADR 0008）。
  japan-open-today は上表の 6 種を `crawlable_operator_kinds` として宣言する
- 運営主体の根拠は `/data/` に一覧表示し、どの施設をなぜ巡回しているか説明できる状態を保つ

## 追記（2026-09-12）: 最初の 14 件で pending が 0 件になった経緯

S4 でいったん 5 件を `policy: pending` にしたが、もう一段自動で探したところ全件で根拠が取れた。
**「レビューに回す前にもう一段」の一段が何だったか**を残しておく。

| 対象 | 取れた根拠 | どこにあったか |
|---|---|---|
| 地中美術館・ベネッセハウス・豊島美術館 | 「…株式会社ベネッセコーポレーションと公益財団法人 福武財団が展開しているアート活動の総称です。」 | `benesse-artsite.jp/about/`（施設ページではなくサイト全体の「〜とは」） |
| 四国汽船 | 「商号 四国汽船株式会社 所在地 本社 …」 | `shikokukisen.com/company/`（会社情報ページ） |
| 高松城跡 玉藻公園 | 「史跡高松城跡(高松市立玉藻公園) … Copyright © Takamatsu City」 | **高松市の公式サイト**に情報源を移した |

### 収穫 1: 法人名の空白でパターンが外れていた
`(?:公益財団法人|…)[^\s、。（(]{2,30}` は「公益財団法人 福武財団」のように**法人格のあとに空白が入る**
書き方に一致しない。空白で最初の文字が外れ、2 文字以上の条件を満たさずに一致失敗する。
その結果「根拠が取れない」と誤判定して 3 件をレビューに回していた。
**根拠が取れないときは、まずパターン側を疑う**。運営主体の記述は普通どこかに書いてある。

### 収穫 2: 施設ページに無くてもサイト全体のページにある
運営主体は施設の紹介ページではなく、「〜とは」「会社情報」「概要」に書かれている。
最初の収集はトップと概要ページの 2 段だけだったので、探す範囲を増やした。

### 収穫 3: robots.txt が取得できないときの扱い
`takamatsujyo.com` は robots.txt の取得自体ができない（接続拒否）。
**取得できない＝許可されていないと見なして巡回しない**（sitemill の `RobotsCache` が
`deny_all` で扱う既定の挙動。事業側の判断と一致）。
一方で、その施設の一次情報が**別の公式サイト（この場合は高松市）にある**なら、情報源をそちらに移す。
巡回できないサイトはリンクとしてだけ案内する（`external_links`）。

### 影響
- レビュー行列（`data/review/kagawa.yaml`）は空。人間の判断を待たずに 16 情報源すべてを巡回できる
- 「根拠が取れない」を報告する前に、パターンの取りこぼしと探索範囲の不足を確認する手順を加えた

## 追記（2026-09-12）: URL は推測せず、名前が本文にあることを確かめる

**屋島の情報源に、別の施設の URL を seed していた。** 県観光協会の一覧の ID を推測して
`my-kagawa.jp/point/29` を当てたが、これは東かがわ市の「つばさ山温泉」のページで、
温泉の営業時間（10:00〜22:00）・入浴料（500円）・住所・電話を**屋島の事実として公開していた**。
正しいページはリンクから辿れる `point/298`（見出し「屋島(山上)」）だった。

Commons のカテゴリ名で学んだのと同じ失敗である（S3: カテゴリ名を推測せずリンクを辿る）。
対象が変わっても原因は同じなので、原則として書く。

1. **URL は必ずリンクから辿って確定する。** ID・スラッグを組み立てて URL を作らない。
   辿れなければ「情報源なし」として記録する
2. **施設の素性を決めるページ（`spot_detail`）は、その施設の名前が本文にあることを確かめる。**
   無ければ取り込まない（`name_mismatch` として数える）。名前が離れて書かれること
   （「史跡高松城跡」と「玉藻公園」）はあるので、語に割ってすべて含まれていれば同じ施設とする
3. **seed から外した URL の巡回状態は捨てる。** 状態が残っているかぎり抽出は続き、
   外した判断が効かない（sitemill の `declared_pages_only` を宣言する）
4. 施設自身の事実だけを取る。同じページにある駐車場・売店・カフェ・隣接施設の時間や料金を
   その施設のものとして引用しない（プロンプト `spot_v2`）

この 4 つは、①ゲートのある施設の全域展開（数十件規模）に入る前に必要だった。
1 件ずつ目で見られる 12 件では見逃しても気づけるが、100 件では気づけない。

## 追記（2026-09-17）: 判定できない運営主体の既定値を「施設の公式」にしない

**運営主体を判定できなかった情報源が、レビューに回らず自動で採用されていた。** `tools/seed_spots.py` の
`_operator_kind` は、ホスト・引用のどの規則にも当たらないと既定で `facility_official` を返していた。
根拠の引用を探す正規表現も緩く、「運営」「管理」「主催」の後に空白があれば何でも拾ったため、
「主催 | 実施形式 1937年…」「管理 37.5°C以上の発熱のある方…」が根拠として記録され、**21 件が
「施設の公式」として巡回されていた**。「情報を尽くしても判定できない案件だけをレビューに回す」という
この ADR の原則が、既定値で骨抜きになっていた。

自治体のサイトは種別をホストで決めるので判定は正しかったが、根拠として記録・表示していた引用が
市サイトのメニュー（「情報公開・個人情報保護・監査」）や本文の無関係な文で、**根拠として意味を成していなかった**
（自治体系 32 件）。`/data/` のページにはこの引用がそのまま出ていた。

**決定**:
- `_operator_kind` の既定を `unknown` にする。引用から運営者の名前（法人格つき、または「運営: 〜」の明記）が
  取れたときだけ `facility_official` と読み、取れなければ `policy: pending` でレビュー行列に回す
- 運営主体の名前が読めなければ空にする（引用の先頭を名前にしない）
- 根拠の引用は、見出しの語のあとにコロンがある書き方だけを拾う
- 自治体・県のサイトの引用は、フッターの著作権表記（「Copyright (C) Sakaide City. All Rights Reserved.」）、
  無ければ住所か法人番号を伴う名乗り（「三木町役場 ｜ 〒761-0692 …」）にする。「市役所」の語だけでは拾わない

**既存の情報源の洗い直し（53 件）**: 公式ページと、そこからリンクで辿れる会社概要・運営者のページを読み直し
（`tools/verify_operators.py`、記録は `data/runs/operator-verification.json`）、引用がページに実在することを
取り直して確かめてから反映した。**第三者のサイトは混ざっていなかった**。

### 取り込みで止める検査（`japan_open_today.operators.operator_problems`）

同じ形の失敗は 3 回目（観光協会 10 件、自治体 24 件、今回）。書き込む道具を直しても、別の道具や手編集で戻る。
そこで次の 2 つを、**取り込みの道具（`tools/seed_spots.py`）と、情報源の全件を読むテスト（CI の checks）の
両方**で確かめる。どちらも同じ関数を呼ぶ。

1. **運営者の欄が名前であること**。引用符の片割れ、文の語尾（〜しました・〜による・〜に関して）、
   見出しの語（沿革・所在地・概要）、著作権表記、ページ題名の区切り（｜、` - `）、法人格だけ、を断片とみなす
2. **`facility_official` は、根拠の引用に運営者の名前が出てくること**（空白の有無は問わない。
   「A・B」は両方を探す）。英字で名乗っているときは引用の中の表記を `operator_evidence.name_in_quote` に
   書き、その表記が引用にあることを確かめる。法人名がサイトに無いときは `operator_note` に理由を書いた場合だけ通す

取り込みの道具は、問題があれば書き込まずに `policy: pending` にしてレビュー行列に回す。
自治体・観光協会は種別をホストで決めるので、2 は `facility_official` にだけ課す（英字の著作権表記
「Copyright © Takamatsu City」も自治体の名乗りとして通す）。検査はサービス固有の種別に依るので jot 側に置いた。
