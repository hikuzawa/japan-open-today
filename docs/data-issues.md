# データの誤り（別の課題として残すもの）

見つけたが、その場では直していないデータの誤り。**直すときは読み取り側（抽出・判定の規則）を直す**。
値を手で書き換えない（次の巡回で元に戻る。sitemill ADR 0024）。

## 1. 運営主体（`operator`）が施設の運営者ではなく、引用も根拠になっていない（2026-09-17）

**対応済み（2026-09-17）**。既定値を `unknown` に変え、53 件を洗い直して反映した。第三者のサイトは無かった。
経緯と結果の内訳は ADR 0009 の追記。以下は見つけた時点の記録。

### 何が起きているか

`data/sources/kagawa.yaml` の `operator` は、`tools/seed_spots.py` の `_operator_name` が根拠の引用から
切り出したもの。法人名や「指定管理者: 〜」が見つからないと**引用の先頭 60 字をそのまま入れる**。
その結果、35 件の情報源で次のような文字列が運営主体になっている。

| `operator` に入っている文字列 | 件数 | 種別 | 実際 |
| --- | ---: | --- | --- |
| 「情報公開・個人情報保護・監査」「新着情報」など市サイトのナビゲーション | 20 | `municipality` | 市のサイト |
| 「三豊での観光をより便利に快適に楽しくでいただくため…」 | 8 | `facility_official` | 三豊市観光交流局のサイト |
| 「指定管理者である公益財団法人高松市文化芸術財団の事務局主幹をお招きし…」 | 4 | `municipality` | 高松市のサイト |
| 「主催 \| 実施形式 1937年5月5日~6月16日…」 | 3 | `facility_official` | 四国八十八ヶ所霊場会のサイト |

施設ページには出していないが、根拠の引用は `/data/` のページにそのまま出ていた。

### 判定に効いているか

- **巡回の可否**（sitemill ADR 0017）は `operator_kind` で決まり、`operator` の文字列は使わない
- **`municipality`（自治体）の 24 件**: 種別は URL のホスト（`lg.jp` など）で決まっていて、判定は正しい。
  根拠の引用がナビゲーションの文字列で、**ADR 0009 の「運営主体の根拠（引用と URL）」として意味を成していない**
- **`facility_official` のうち 21 件は、判定そのものが根拠なしで決まっている**。`_operator_kind` は
  ホストにも引用にも当たらないと**既定で `facility_official` を返す**ので、運営主体を判定できなかった情報源が
  人間レビュー（ADR 0009）に回らず、自動で採用されている

| ホスト | 件数 | 引用 |
| --- | ---: | --- |
| `mitoyo-kanko.com` | 8 | 案内文の一部（観光交流局と読める語が切れている） |
| `88shikokuhenro.jp` | 3 | 「主催 \| 実施形式 1937年…」 |
| `konpira.or.jp`・`shikoku-cable.co.jp`・`komatsuoji.com` ほか | 各 1 | 著作権表記（`© 2025 Shikoku` など）。サイトの持ち主の根拠にはなりうる |
| `e-mikado.jp` | 1 | 「37.5°C以上の発熱のある方…」 |
| `takamatsu.or.jp` | 1 | 「事務局 荻生) カレンダー 2026年8月…」 |
| `sanuki.ne.jp`・`ogijima.site`・`shorinjikempo.or.jp`・`hoshoin.jp`・`michinoeki-kotohiki.com` | 各 1 | 運営主体の語が無い |

いずれも施設や観光団体の公式らしいサイトだが、**そう判定した根拠がデータに無い**。
第三者のサイトが混ざっていないかは、1 件ずつ確かめるまで分からない。

### 直し方の見当

- `_operator_kind` の既定を `facility_official` ではなく「判定できない（`unknown`、`policy: pending`）」にする。
  ADR 0009 のとおりレビュー行列に回り、発見側で運営者表記（著作権表記・会社概要・指定管理者の表記）を
  辿り直す。レビュー待ちが 10 件を超えるなら発見側を先に直す
- `_operator_name` は、名前が取れなければ空にする（引用の先頭を名前にしない）
- 自治体の 24 件は、ホストで決まることを根拠として書く（引用はナビゲーションではなく、ホストの種別と URL）

## 2. 開館の規則の「第 n 週」が落ちる（2026-09-17、判定には歯止めを入れた）

鬼無植木盆栽センター（`kinashi-bonsai`）は原文が「9月から6月までの第2・4水曜日 8:00頃~16:00頃」だが、
開館の規則（`HoursPeriod.days`）は曜日の選び方しか持てず「毎週水曜」になっている。
**第 3・第 5 水曜日も「開館」と判定していた**（2026-09-16 は第 3 水曜で「開館」と出ていた）。

- 当面の歯止め: 開館の規則の引用に第 n 週の指定があれば、判定を「不明」にし理由 `rule_unsupported` を出す
  （`japan_open_today/verdict.py` の `hours_unrepresentable`）。施設ページの営業時間も原文だけを出す
- 本来の直し方: sitemill の `DaySelector` に第 n 週（`nths`）を持たせ、抽出と判定の両方で扱う
  （休館日の規則 `ClosureRule` にはすでにある）
- 該当は 2026-09-17 時点で 1 施設

## 3. 「〜6月」の月末を 31 日として持っている（2026-09-17、表示だけ直した）

季節の期間（`AnnualSpan`）の終わりが、月の日数に関わらず 31 日になっている（2・6・9・11 月で 8 期間）。
含まれるかの計算は月日の大小なので判定は変わらないが、そのまま出すと「6月31日」になる。

- 表示: 終わりの日がその月の日数以上なら「6月末」と出す（`pages._hours_display`）
- 本来の直し方: 読み取りで月末の日にする（`AnnualSpan` の検証で存在しない日を拒む）
